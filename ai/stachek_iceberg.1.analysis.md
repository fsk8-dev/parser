# Технический анализ модуля stachek_iceberg.py

## 1. Назначение модуля
Модуль `stachek_iceberg.py` предназначен для парсинга расписания катка "Стачек Айсберг" из постов ВКонтакте. Основная функция модуля - извлекать информацию о сеансах массового катания и преобразовывать её в структурированный формат.

## 2. Публичное API

### Функции:
1. `get_day_schedule_list(text, sport_schedule_pattern)`
   - Парсит текст с расписанием и возвращает список объектов `DaySchedule`
   - Принимает: текст расписания и шаблон для поиска
   - Возвращает: список объектов `DaySchedule`

2. `get_arena_schedule_list(post, skating_schedule_pattern)`
   - Создает расписание для арены на основе поста
   - Принимает: пост и шаблон расписания
   - Возвращает: список объектов `ArenaSchedule`

3. `get_stachek_iceberg_schedule_list()`
   - Основная функция модуля
   - Получает посты из ВКонтакте и преобразует их в расписание
   - Возвращает: список объектов `ArenaSchedule`

## 3. Поток данных

### Входные данные:
- Посты из ВКонтакте (через `get_post_list`)
- Шаблоны регулярных выражений для парсинга

### Выходные данные:
- Список объектов `ArenaSchedule`, содержащих расписание сеансов

### Преобразование данных:
1. Получение постов через `get_post_list('icebergkatok')`
2. Извлечение актуального поста через `get_post`
3. Парсинг расписания с помощью регулярных выражений
4. Преобразование в объекты `DaySchedule` и `ArenaSchedule`

## 4. Зависимости

### Внутренние:
- `classes.day_schedule.DaySchedule` - для хранения расписания на день
- `utils.get_time_obj.get_time_obj` - для преобразования времени
- `vk_utils.get_post_list.get_post_list` - для получения постов ВКонтакте
- `vk_utils.get_post.get_post` - для извлечения актуального поста
- `classes.arena_name.ArenaName` - перечисление названий арен
- `classes.arena_schedule.ArenaSchedule` - для хранения расписания арены
- `classes.location_id.LocationId` - идентификаторы локаций
- `classes.arena_id.ArenaId` - идентификаторы арен
- `classes.schedule_type.ScheduleType` - типы расписаний

### Внешние:
- `re` - для работы с регулярными выражениями
- `datetime` - для работы с датами и временем

## 5. Побочные эффекты

- Выполняются сетевые запросы к API ВКонтакте через `get_post_list`
- Вывод в консоль через `print(arena_schedule_list)` в функции `get_stachek_iceberg_schedule_list`

## 6. Потенциальные ошибки и слабые места

1. **Обработка ошибок API ВКонтакте**:
   - Нет обработки ошибок при недоступности API
   - Нет проверки на пустой ответ от API

2. **Валидация данных**:
   - Нет проверки формата входных данных
   - Нет обработки случая, когда пост не содержит ожидаемого расписания

3. **Временные зоны**:
   - Используется локальное время системы без учета временной зоны

4. **Жестко закодированные значения**:
   - ID группы ВКонтакте 'icebergkatok' захардкожен в коде
   - Шаблоны регулярных выражений определены внутри функций

## 7. Риски при рефакторинге

1. **Изменение структуры ответа API ВКонтакте**:
   - Модуль полагается на определенную структуру постов
   - Изменение формата постов может сломать парсинг

2. **Изменение формата расписания**:
   - Модуль использует жестко закодированные шаблоны регулярных выражений
   - Изменение формата расписания потребует обновления шаблонов

3. **Зависимость от структуры классов**:
   - Модуль тесно связан с классами из пакета `classes`
   - Изменение сигнатур конструкторов или структуры классов потребует обновления модуля

4. **Проблемы с производительностью**:
   - При большом количестве постов возможны задержки из-за последовательной обработки
   - Нет кэширования результатов запросов
